# 06 故障排查

## GitHub、Docker 或依赖下载失败

CMD：

```bat
set http_proxy=http://127.0.0.1:7892
set https_proxy=http://127.0.0.1:7892
```

PowerShell：

```powershell
$env:HTTP_PROXY='http://127.0.0.1:7892'
$env:HTTPS_PROXY='http://127.0.0.1:7892'
$env:ALL_PROXY='http://127.0.0.1:7892'
```

确认本机 7892 端口的代理程序正在运行。如果代理没启动，设置变量反而会让所有下载失败。

## 烧录提示找不到 COM 口

- 换支持数据的 USB 线；
- 查看设备管理器；
- 安装开发板对应的 CP210x/CH343 驱动；
- 关闭串口监视器；
- 尝试 BOOT + RESET 下载模式。

## 节点能联网但服务端没有数据

依次检查：

1. `target-ip` 是电脑 IPv4，不是路由器 IP；
2. 端口为 UDP 5005；
3. Windows 网络类型为专用；
4. 防火墙规则存在；
5. 路由器没有客户端隔离；
6. 服务端带有 `--udp-bind 0.0.0.0`；
7. `--udp-allow` 的 CIDR 包含节点；
8. 没有另一个程序占用 UDP 5005。

查看占用：

```powershell
Get-NetUDPEndpoint -LocalPort 5005 -ErrorAction SilentlyContinue
```

## DevKitC 有心跳但 CSI 包率为 0

不要直接使用启用显示探测的通用 8 MB Release 包。按本教程使用 `sdkconfig.defaults.devkitc` 从源码构建。官方文档说明无屏 DevKitC 上的显示误探测可能使 CSI 产出降为 0。

## 页面有动画但节点没有数据

检查是否使用了 `auto` 或 `simulated` 数据源。重新用 `--source esp32` 启动。真实源没有数据时应该明确显示无节点，而不是生成演示数据。

## Docker 服务端收不到 Windows 上的 UDP

Docker Desktop 可能重写 UDP 源地址，导致 `RUVIEW_UDP_ALLOW` 不匹配。新手优先按教程使用 Windows 原生 Rust 服务端。若坚持 Docker，需要按照上游 `docs/TROUBLESHOOTING.md` 使用 UDP relay 和对应网桥地址。

## ESP32 很热

持续 CSI 会关闭 Wi‑Fi 省电。全尺寸 DevKitC 应保持通风；如果烫手、出现掉线或重启，立即断电。不要将运行中的板子包在泡棉、胶带或密闭外壳内。

## 效果时好时坏

- 路由器自动换信道；
- 2.4 GHz 干扰严重；
- 节点或路由器位置移动；
- 空调风、窗帘、风扇造成环境运动；
- 单节点几何信息不足；
- 在别人的房间训练的模型不适合你家。
