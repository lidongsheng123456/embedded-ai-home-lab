# 有AI帮写代码，你还应该学什么

**不用背完所有函数。先学会：接对电、看懂数据怎么走、用日志判断哪里没工作。**

| 先学什么 | 你要能做到 | 用哪个实验练 |
| --- | --- | --- |
| 电源与共地 | 分清3.3V和5V；知道GPIO不能给舵机供电 | LED限流、MQ-2分压 |
| 输入与输出 | 知道按钮按下为什么读到低电平 | 按键点灯 |
| 串口排错 | 分清“电脑显示输入”和“芯片真的收到” | 发送`p`收到`PONG` |
| 时间与PWM | 分清周期、占空比、脉宽 | 呼吸灯、舵机 |
| 常用连接方式 | 能接线、选地址或片选，不必默写底层驱动 | OLED、74HC595 |
| 多件事一起做 | 知道长延时会影响什么 | 状态机、FreeRTOS任务 |
| 验证结果 | 分清编译、烧录、实物通过 | 每次只接一个新模块 |

## 代码可以交给AI，下面几件事要亲手核对

| AI可以帮忙 | 你负责确认 |
| --- | --- |
| 写HAL、Arduino初始化代码 | 实物型号、引脚、电压是否对应 |
| 生成引脚表和接线图 | 是否占用USB、内存或另一个模块的脚 |
| 计算电阻和电源预算 | 用万用表测电压，观察启动时是否复位 |
| 接传感器库、写网页 | 读数是否随真实环境变化，是否仍在演示模式 |
| 分层、写注释、做自动测试 | 断线、断网和连续运行时是否符合预期 |

遇到陌生词再查[新手词典](../../docs/00-新手名词解释.md)，不用先背一遍。

## 推荐顺序：先STM32，再ESP32，最后整机

| 阶段 | 做到什么就继续 | 入口 |
| --- | --- | --- |
| STM32基础 | 点灯、读按钮、收发串口、调PWM、读电位器、显示OLED | [HAL课程](STM32F103-HAL课程.md) |
| ESP32联网 | 串口排错、读模块、网页控制、任务传数据、认识PSRAM | [Arduino课程](ESP32-S3-Arduino课程.md) |
| HomeGuard Mini | 每次加一个模块，最后组合运行、断线恢复、连续48小时测试 | [项目第一步](../../projects/homeguard-mini/docs/00-先从这里开始.md) |

STM32与ESP32的GPIO、ADC、串口原理相通，不必机械重学。重点比较两者的引脚限制与库用法。

## 哪些现在学，哪些以后查

| 内容 | 当前要求 |
| --- | --- |
| GPIO、UART、ADC、I2C、SPI | 会接、会看现象、会查错。 |
| 时钟、中断、定时器 | 知道谁在计时，事件在哪里处理；不用背完整时钟树。 |
| PWM | 调灯看占空比；普通角度舵机看高电平持续时间。 |
| Wi-Fi、IP、网页 | 会连家庭网络、找设备IP、识别断网与热点。 |
| FreeRTOS、队列 | 会把不同工作分开，用队列传数据，避免乱改全局变量。 |
| DMA | 知道它能替CPU搬数据，遇到大量采样再深入。 |
| 低功耗 | 做电池设备再学；必须测电流，不能靠“程序睡了”判断省电。 |
| BLE、PSRAM、I2S、相机 | 按项目需要学；相机和音频先单独验机。 |
| 寄存器地址、全部库函数、字体数组 | 会查即可，暂时不背。 |

## 用一条路线检查AI写的程序

```text
电脑发送字符“1”
→ ESP32转发
→ STM32收到0x31
→ 命令解释成45°
→ PA6输出设定的舵机脉宽
→ 有合格供电的舵机产生动作
```

没有转动时逐段找证据：有没有日志、有没有收到命令、角度是否变化、电源是否正常。串口显示45°只能证明程序更新了目标，不能证明实物转到了45°。

## 每次实验只记四项

1. **接了什么**：型号、供电、GPIO。
2. **烧了哪个环境**：例如`05c_uart_servo`。
3. **看到了什么**：日志、画面、数值或动作。
4. **怎样证明**：换输入后结果是否按预期变化。

只出现`SUCCESS`表示编译通过；上传完成表示烧录通过；真实现象符合预期才是实物验证。HomeGuard用于学习和辅助提醒，不能替代认证烟雾、燃气或一氧化碳报警器。
