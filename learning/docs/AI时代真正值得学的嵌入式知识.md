# AI时代真正值得学的嵌入式知识

这份指南不要求你脱离AI默写代码。目标是让你能够使用AI完成项目，同时判断代码和接线
是否可靠，遇到问题时知道从哪里检查。

## 先说结论

AI可以快速生成代码，但它不能替你承担这些后果：

- 把5V信号接进只能承受3.3V的GPIO；
- 同一个引脚同时分配给屏幕和摄像头；
- 舵机电流太大，导致开发板不断复位；
- 模块实物针序与商品资料不一致；
- 程序编译成功，但传感器实际上没有工作；
- 设备只运行了几分钟，却被误认为已经稳定。

因此，你不需要成为“能默写全部驱动的人”，而应该成为：

> 能看懂AI的方案、保证硬件安全、验证真实现象，并根据证据排查问题的人。

## 最值得学的七种能力

### 1. 电压、电流、供电和共地

这是第一优先级，因为接错可能损坏硬件。

至少要能回答：

- 模块使用3.3V还是5V供电？
- 模块输出给GPIO的信号最高是多少伏？
- GPIO是在传递信号，还是在给负载供电？
- 舵机、电机、喇叭、灯带是否需要独立电源或驱动器？
- 两块板通信时为什么必须连接GND？
- 什么情况下需要电阻、分压或MOS管？

通俗理解：

```text
电压：推动电流的“压力”
电流：实际流过的“流量”
GND：大家共同使用的0V参考点
GPIO：传递小信号的小门，不是大功率电源插座
```

例如MQ-2使用5V加热，但AO可能接近4V。ESP32-S3的GPIO只能接收约0～3.3V，因此AO必须
先经过分压。AI可以计算电阻，最终仍应由你用万用表确认分压点没有超过3.3V。

### 2. 看懂程序的数据路线

不要求从空文件开始写代码，但要能找到：

- 程序入口在哪里；
- 引脚在哪里配置；
- 哪个函数读取传感器；
- 哪个条件触发报警；
- 哪个函数控制舵机或屏幕；
- 阈值、时间和Wi-Fi配置在哪里修改。

例如串口控制舵机的数据路线是：

```text
电脑输入字符“1”
  → ESP32-S3转发
  → STM32串口收到字符
  → 程序把“1”解释成45°
  → 定时器改变PA6的PWM脉宽
  → 舵机转向目标位置
```

看到AI修改代码后，至少要能沿着这条路线检查每一段，而不是只看它说“已经完成”。

### 3. 串口日志和故障排查

UART串口相当于单片机的嘴巴。没有日志时，你只知道“没反应”；有日志后可以判断：

- 程序有没有启动；
- 命令有没有收到；
- 传感器有没有找到；
- 当前ADC读数是多少；
- 摄像头在哪一步初始化失败；
- 开发板是不是不断重启。

需要真正理解：

```text
TX接对方RX
RX接对方TX
GND互连
两边波特率一致
字符“1”和数值1不是同一个字节
```

排错时一次只改变一个条件，并保存改变前后的日志。这个能力比背HAL函数更有价值。

### 4. 时间、PWM、中断和并发

嵌入式程序通常要一直运行，并同时处理多个功能：

```text
读取传感器、刷新屏幕、处理按键、接收网络请求、控制蜂鸣器
```

需要理解：

- 延时会不会阻塞其他功能；
- 周期和频率是什么；
- PWM的高电平时间和占空比是什么；
- 中断为什么适合处理突然到来的事件；
- 状态机怎样让多个步骤轮流执行；
- FreeRTOS任务怎样分工，任务之间怎样安全传递数据。

不同设备对PWM的理解也不同：

| 设备       | 主要关注什么                         |
| ---------- | ------------------------------------ |
| LED        | 高电平占整个周期的比例，也就是占空比 |
| 直流电机   | 平均获得的能量，通常也看占空比       |
| 无源蜂鸣器 | 每秒重复多少次，也就是频率           |
| 舵机       | 每次高电平持续多少微秒，也就是脉宽   |

### 5. UART、I2C、SPI、ADC分别解决什么问题

不用一开始手写底层协议，但必须会选择、接线和排错。

| 名称 | 通俗理解                   | 常见设备            | 最低学习目标                   |
| ---- | -------------------------- | ------------------- | ------------------------------ |
| UART | 两个人各用一根线互相说话   | 电脑、LD2410C、GPS  | 会交叉TX/RX、设置波特率        |
| I2C  | 多个有地址的设备共乘一辆车 | SHT40、BH1750、OLED | 会检查地址、上拉和总线共享     |
| SPI  | 使用多根线高速传输         | TFT屏幕、存储器     | 理解时钟、数据线和CS片选       |
| ADC  | 把电压转换成数字           | MQ-2、电位器、电池  | 会算电压、分压和允许范围       |
| PWM  | 用重复脉冲表达控制要求     | LED、舵机、电机     | 会区分周期、频率、脉宽和占空比 |

### 6. 电源、引脚和内存预算

完整项目失败，经常不是代码语法问题，而是资源不够或互相冲突。

需要检查：

- 所有模块的电流相加后，电源是否足够；
- 舵机或Wi-Fi启动瞬间是否拉低电压；
- 一个GPIO是否被两个模块重复使用；
- 某些GPIO是否已被Flash或PSRAM占用；
- 串口、定时器、I2S和DMA通道是否冲突；
- 摄像头图片是否需要PSRAM；
- 杜邦线是否太长，导致高速信号不稳定。

AI生成引脚表以后，仍要由你逐项核对开发板针脚图和模块实物丝印。

### 7. 分阶段验证和安全边界

不要第一次就把所有模块插满面包板。正确方法是：

```text
只接开发板并烧录
  → 加屏幕并验证
  → 加一个传感器并验证
  → 加下一个模块
  → 最后组合完整系统
```

同时区分三种结论：

```text
编译通过：代码可以生成固件
烧录通过：固件成功写入芯片
实物验证：真实接线产生了预期现象
```

编译通过不能证明摄像头有画面，也不能证明气体传感器数值准确。

## 原学习路线应该怎样取舍

### STM32F103：用来建立硬件直觉

| 内容     | 建议       | 真正要学什么                                       |
| -------- | ---------- | -------------------------------------------------- |
| GPIO     | 必学       | 输入、输出、上拉、下拉、推挽和高低电平             |
| 系统时钟 | 理解概念   | 时钟影响执行速度、定时器和波特率，不必背完整时钟树 |
| EXTI中断 | 学一个案例 | 区分轮询和硬件主动通知                             |
| UART     | 重点学习   | 日志、命令、波特率、TX/RX和ASCII                   |
| TIM/PWM  | 重点学习   | 周期、频率、占空比、脉宽以及舵机控制               |
| ADC      | 必学基础   | 电压、分辨率、分压、噪声和平均值                   |
| I2C/SPI  | 学会使用   | 地址、片选、共享总线和常见接线错误                 |
| DMA      | 暂时了解   | 知道它能替CPU搬运大量数据，遇到高速采集再深入      |
| 低功耗   | 暂缓       | 做电池设备时再学习休眠、唤醒和功耗测量             |

### ESP32-S3：用来完成联网成品

| 内容             | 建议       | 真正要学什么                            |
| ---------------- | ---------- | --------------------------------------- |
| GPIO             | 快速复习   | 注意ESP32的3.3V限制和特殊引脚           |
| 系统时间与延时   | 重点学习   | 不用长延时卡住网络和传感器              |
| 外部中断         | 学一个案例 | 回调函数要短，不在中断里做复杂工作      |
| UART             | 重点学习   | 调试、串口传感器和开发板桥接            |
| PWM/RMT          | 按项目学习 | 普通PWM与WS2812严格时序不是一回事       |
| ADC              | 必学       | MQ-2分压、原始值、噪声和相对指数        |
| I2C/SPI          | 必学       | 环境传感器和TFT屏幕都需要它们           |
| Wi-Fi            | 重点学习   | STA、AP、IP、路由器、本地网页和断线恢复 |
| BLE              | 可以延后   | 需要手机近距离直连时再学                |
| FreeRTOS         | 重点学习   | 任务分工、非阻塞、队列和共享数据        |
| PSRAM/I2S/摄像头 | 按项目深入 | 大图片、数字音频、高速接线和缓冲区      |

## 可以放心交给AI的工作

- 生成HAL或Arduino初始化样板；
- 查询库函数的具体写法；
- 生成PlatformIO环境；
- 编写网页HTML和CSS；
- 接入常见传感器库；
- 生成JSON、注释和README初稿；
- 格式化代码和拆分重复模块；
- 根据数据手册生成第一版引脚表。

这些内容生成后仍要经过编译和实物验证。

## 不能完全交给AI的工作

- 确认实物模块的型号和针脚顺序；
- 确认电压、电流、共地和散热；
- 用万用表测量真实电压；
- 检查引脚和硬件资源冲突；
- 判断日志是否符合真实现象；
- 确认舵机没有撞到机械限位；
- 完成长时间稳定性测试；
- 判断设备能否用于安全、医疗或其他高风险场景。

## 适合当前项目的精简学习顺序

不要把STM32和ESP32的相同内容机械地学两遍。推荐按下面顺序前进。

### 第一阶段：STM32基础

1. GPIO控制LED和读取按钮；
2. UART打印日志、接收字符；
3. 定时器和PWM控制LED、舵机；
4. ADC读取电位器；
5. I2C驱动OLED；
6. 使用系统运行时间编写非阻塞逻辑。

通过标准：能够用自己的话解释电从哪里来、数据从哪条线走，以及程序为什么产生当前现象。

### 第二阶段：ESP32-S3联网设备

1. 串口日志和重启原因；
2. I2C传感器、SPI屏幕和ADC；
3. Wi-Fi、IP和本地网页；
4. FreeRTOS基本任务和数据传递；
5. PSRAM、摄像头和I2S音频；
6. 电源、引脚和内存的统一规划。

通过标准：能够独立判断故障属于代码、接线、电源、网络还是模块型号问题。

### 第三阶段：HomeGuard Mini完整系统

1. 每次只接入一个模块；
2. 为每个模块记录接线、日志和过关现象；
3. 统一管理引脚、阈值和时间；
4. 避免入口文件同时承担驱动、业务和界面职责；
5. 完成断线恢复、异常输入和连续运行测试；
6. 明确MQ-2等学习模块不能替代认证安全设备。

## 学习时不用背什么

这些内容需要会查，不需要死记：

- HAL结构体的全部字段；
- Arduino库函数的精确拼写；
- STM32所有寄存器地址；
- OLED字体数组；
- 完整TCP/IP、Wi-Fi和BLE协议栈；
- 每种芯片的全部复用引脚；
- 一次用不到的DMA和低功耗细节。

最后记住这个优先级：

```text
硬件安全
  > 看懂数据路线
  > 日志和排错
  > 时间与并发
  > 常用通信原理
  > 电源与资源规划
  > 模块化和验收
  > 背语法和API
```

AI让“写出第一版代码”变得容易了，但判断第一版代码是否安全、正确、稳定，仍然是你最值得
学习的能力。
