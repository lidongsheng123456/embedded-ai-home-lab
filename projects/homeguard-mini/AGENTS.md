# HomeGuard Mini 项目规约

本目录继承仓库根目录的 `AGENTS.md`。

## 固件分层

```text
firmware/include/domain/   状态数据和业务常量
firmware/include/drivers/  传感器、雷达、麦克风等硬件接口
firmware/include/services/ Wi-Fi、HTTP 等服务接口
firmware/include/ui/       TFT 显示接口
firmware/include/app/      应用调度接口
firmware/src/...           与 include 对应的实现
```

- `src/main.cpp` 只保留 `setup()`、`loop()` 和应用对象组装。
- 传感器模块只负责产生测量值，不决定告警等级。
- 告警判断属于领域规则；蜂鸣器输出属于应用/驱动层。
- Web API 和 TFT 只能读取公开状态或调用公开命令，不能各自复制告警规则。
- 所有引脚继续集中在 `include/pins.h`；阈值和时间间隔集中在领域配置中。
- 修改引脚时同步更新 `docs/03-接线教程.md`；修改功能边界时同步更新 `docs/01-项目原理.md`。

## 验证

- 固件修改后在 `firmware/` 执行 PlatformIO Build。
- 未连接传感器时只能声明编译通过，不能声明采集精度或告警行为已实测。
- `include/app_config.h` 含本机 Wi-Fi 信息，禁止提交或输出其内容。

## 文档与目录维护

- `docs/00～08` 保存实际制作教程，`09` 保存 DeepSeek 配置，`10` 保存当前缺陷、修复和待验清单；编号连续，调整后同步修复入口和链接。
- 网页使用、家庭模型和前端结构统一维护 `firmware/web/README.md`，不再新增重复的网页改造或轮次审查文档。
- 全部硬件资料集中在 `eda/`：工作工程保持完整，设计、说明和工具放 `eda/hardware/`；禁止重新建立项目顶层 `hardware/`。
- 新增文件前先查找已有职责相同的文件，优先更新。删除过时说明前把仍有用的操作、限制和来源合入对应入口，并修复所有链接。
- 临时候选、导出、截图、依赖和过程日志只进已忽略目录；检查结论更新已有验收清单，不复制成多份总结，不在项目内建立发布包或备份目录。
- 原生 EDA 工程与源码统一通过本仓库 Git 管理，按可审查的职责分组提交，提交说明使用中文。以已验证提交作为回退节点，不再反复创建备份工程或备份目录；需要 Gerber、物料或坐标时从当前 PCB2 生成，原生工程与设计结论随 Git 提交保留。
- 当前供电为保护后 5V 接母座 J7.21；开发板 IN/OUT 按厂家图短接。烧录前先断电取下，拔电脑 USB 后再装回。不复活旧 J11 短 USB 方案。
