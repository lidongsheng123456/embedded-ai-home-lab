# 01 项目原理和功能边界

## 一句话理解

HomeGuard Mini是一台由ESP32-S3控制的本地环境学习机：传感器负责“感觉”，规则和AI负责
“判断”，屏幕、网页、蜂鸣器和摄像头负责“告诉你发生了什么”。

## 系统结构

    MQ-2 ── ADC ─────┐
    SHT40/BH1750 I2C ┤
    LD2410C ─ UART ──┤
    INMP441 ─ I2S ───┤
    OV2640 ─ DVP ────┼── ESP32-S3 ── ST7789屏幕
    按钮 ─ GPIO ─────┤             ├─ 蜂鸣器
    Wi-Fi ───────────┘             └─ 手机本地网页

电脑只负责开发和烧录。程序烧进去以后，ESP32-S3可以独立运行。网页也保存在ESP32-S3
内部，本地功能不需要Java、Python、Docker或云服务器。可选的DeepSeek环境解读由ESP32
直接访问官方服务，需要联网和密钥，见[云解读教程](09-DeepSeek云解读.md)。

## 每个模块负责什么

| 模块 | 日常比喻 | 产生的数据 |
|---|---|---|
| MQ-2 | 对多种气体都敏感的鼻子 | 原始ADC、模块AO电压、0～100相对指数 |
| SHT40 | 温湿度计 | 摄氏温度、相对湿度 |
| BH1750 | 光照计 | lux光照值 |
| LD2410C | 能发现静坐人员的雷达 | 有人、移动 |
| INMP441 | 数字耳朵 | 0～100相对声音指数 |
| OV2640 | 眼睛 | JPEG图片 |
| ST7789 | 本地仪表盘 | 当前数值、状态和IP |

MQ-2不是SCD41的廉价替身。SCD41测量真实CO₂ ppm；MQ-2会同时受到烟雾、酒精、液化气、
天然气以及温湿度影响。本版本因此删除所有CO₂描述，只显示实验性的相对气体指数。

## 固件为什么要分层

固件按职责分成：

    drivers  →  domain  →  app  →  ui/services

- drivers只读取硬件，不决定是否危险；
- domain保存状态、学习模型和判断规则；
- app安排什么时候采集、显示和报警；
- ui负责TFT绘制和内嵌网页资源，浏览器源码放在firmware/web；
- services只负责Wi-Fi、HTTP和API，使用只读状态；
- main.cpp只创建应用并调用setup和loop。

网页命令先由网络模块记录，再由app在主循环里执行静音或重新学习。这样实体按键和网页
共用同一份操作逻辑，网络层不用直接控制蜂鸣器，也不持有AI模型。

手机/电脑访问设备IP后，浏览器用Three.js绘制三维房间，并读取同一份公开状态。
固定标记只表达“是否有人”、明暗只示意照度，房间不是实际户型扫描。网页、家具模型和Three.js都压缩
保存在设备Flash里，无互联网的热点模式也能使用；详细步骤见[大屏说明](../firmware/web/README.md)。

网页每次完成请求后约2秒再次读取`GET /api/status`；不通过COM串口获取数据。
静音和重新学习分别调用`POST /api/silence`、`POST /api/learn`，点击拍照才请求`GET /camera.jpg`。
设备详情还会显示原始ADC、人体移动、环境读数有效性和静音剩余时间；这些状态都由固件提供。
TFT显示和实体按键继续由本机应用层处理，不需要保持网页打开。

这样更换屏幕或摄像头时，不需要重写AI规则；修改报警阈值时，也不会碰硬件协议代码。

## 蜂鸣器怎么响、什么时候停

可以把应用层理解成“报时员”，把驱动层的定时器理解成“负责关铃的人”：

- 普通提醒每3秒启动一次，响100毫秒；较高级别每1秒启动一次，响250毫秒。
- 手动测试响200毫秒，也就是0.2秒，不修改当前风险等级。
- 每次启动时就安排关闭，不需要等网页传完才关闭。静音操作执行后立即取消当前声音。
- 如果创建或启动定时器失败，就关闭输出，不让蜂鸣器一直响。

安排节奏的是`app/alarm_output.cpp`，实际写引脚并定时关闭的是`drivers/buzzer_pulse.cpp`。
这里使用带驱动的有源蜂鸣器模块，高电平表示“开始响”，不是用GPIO直接给大功率蜂鸣器供电。

当前网页传输、拍照、采集和按键仍轮流在主循环执行。慢请求会推迟下一声，甚至漏掉期间的
短按；恢复后不会一次补响很多声。系统定时任务也有调度延迟，以上时长是程序设定值，
不是已经测量的实物波形或严格实时保证。

## AI实际学习什么

每5秒形成一组特征：

    [MQ-2相对指数, 温度, 湿度, log(光照+1), 声音指数]

前120组有效数据用于学习，大约需要10分钟。程序记录每一项的平均值和正常波动，之后把
新数据换算成“偏离平常多少个标准差”，再合成异常分数。

这不是会思考的通用人工智能，也不会自动知道“这是做饭”还是“这是危险”。它只是发现：
当前多个环境指标与学习阶段相比变化很大。

可选的DeepSeek云模型负责把一次测量解释成通俗中文，需要在网页手动点击。另有一句话
控制入口：仅用户明确要求时，模型可提出蜂鸣器短响、静音、恢复提醒或拍照指令。
指令经协议白名单校验后由应用层执行，不修改风险阈值，不控制舵机。
断网时本地模型和固定规则继续工作。

## 固定规则与AI的关系

- 湿度、声音和MQ-2相对指数有实验性固定阈值；
- AI用于发现多个指标共同偏离正常状态；
- 固定规则不会因为重新学习而消失；
- MQ-2阈值没有安全认证意义，只用于课程实验和趋势提醒。

## 摄像头隐私边界

- 网页只有在用户点击时才请求一张JPEG快照；
- 固件不做人脸识别；
- 默认不保存历史照片，也不上传云端；
- 同一局域网中能访问设备网页的人可能看到快照，因此家庭Wi-Fi和设备热点都必须使用
  强密码；
- 不要把摄像头放在涉及他人隐私的位置。

## 当前不会宣称实现的能力

- 不测量CO₂、一氧化碳或准确的可燃气体ppm；
- 不确认发生火灾、燃气泄漏或入侵；
- 不替代认证烟雾、燃气、一氧化碳报警器；
- 不自动控制220V电器；
- 不做人脸识别和人员身份判断；
- 不把MQ-2或摄像头结果当作生命安全依据。

正确定位是：它是一套完整的嵌入式学习系统和辅助提醒设备。
