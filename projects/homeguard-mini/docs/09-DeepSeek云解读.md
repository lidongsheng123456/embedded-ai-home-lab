# 09 用 DeepSeek 读懂环境数据

## 目标：让设备把数字解释成人话

原来的本地模型像“记住房间平时什么样的小本子”，负责发现变化。DeepSeek 则像一位
“看着仪表盘给你解释的助手”，把一次测量整理成简短中文建议。两者分工不同，可以同时使用。

这一版实现的是：打开设备网页 → 点击“请 AI 解读当前环境” → ESP32 直接联系 DeepSeek
官方服务 → 网页显示文字。电脑只负责打开网页，不需要启动 Java、Python 或代理服务。

网页还提供一句话控制入口，例如“让蜂鸣器响一下”。模型只能提出固件允许的操作，
真正的GPIO输出、静音计时和相机取帧都在ESP32主循环执行。

没有配置密钥时，本地监测、屏幕、网页和报警仍然可用。云解读不会自行改变告警等级。

## 器件、接线和网络

不增加元器件，继续使用已经接好的 HomeGuard Mini。先按[首次启动教程](05-首次启动.md)
确认传感器和网页工作，再增加这项功能，方便判断问题出在哪一步。

ESP32 必须连接能访问互联网的家庭 Wi-Fi。手机连上设备自己创建的热点，只能访问本地
网页，不能因此让 ESP32 自动借用手机流量。电脑上配置的 `http_proxy` 也不会自动传给 ESP32。

## 第一步：在自己电脑上保存密钥

密钥就像“允许程序花费账户额度的门卡”。在 DeepSeek 官方控制台创建 API Key，别把它
贴到聊天、网页截图、串口日志或 Git 中。

- [官方控制台](https://platform.deepseek.com/)：管理密钥和账户。
- [用量页面](https://platform.deepseek.com/usage)：查看费用，不能作为程序调用地址。
- 程序实际调用：`https://api.deepseek.com/chat/completions`，已经固定在固件中。

在 VS Code 打开 `projects/homeguard-mini/firmware`，把 `include/cloud_config.example.h`
复制一份，命名为同目录下的 `cloud_config.h`。也可以在该目录运行：

```powershell
Copy-Item include/cloud_config.example.h include/cloud_config.h
```

如果你已经配置过，直接编辑原来的 `cloud_config.h`，不要用模板覆盖它。

在自己的文件里填写：

```cpp
// 只有启用并填入非空密钥后，固件才创建云解读后台任务。
#define HOMEGUARD_DEEPSEEK_ENABLED true
#define HOMEGUARD_DEEPSEEK_API_KEY "在这里填写自己的密钥"
#define HOMEGUARD_DEEPSEEK_MODEL "deepseek-flash"
```

模型名称按当前官方文档选择；以后官方调整模型时，以账户实际支持的名称为准。本仓库
的本机配置已经被 Git 忽略。密钥会编进固件，因此不要分享配置文件或包含密钥的固件包。
浏览器只会看见“是否配置”和模型名，看不到密钥。

## 第二步：编译并烧录

按[软件与烧录](04-软件与烧录.md)选择你的屏幕环境。例如 1.54 寸 ST7789 核心系统：

```powershell
pio run -e core_st7789_154
pio run -e core_st7789_154 -t upload
pio device monitor -e core_st7789_154
```

已经通过摄像头验收的完整系统使用 `full_st7789_camera`；旧 ILI9341 屏使用
`core_ili9341_240x320`。`camera_ov2640_check` 只诊断摄像头，不提供网页或云解读。

如果命令行没有 `pio`，在 PlatformIO 的 **PROJECT TASKS** 中展开对应环境，点击
**Build**、**Upload**、**Monitor**，效果相同。修改密钥后要重新编译烧录。

## 第三步：在网页点击解读

1. 从串口或 TFT 上找到设备 IP，用手机或电脑浏览器访问。
2. 找到“读懂家里的小变化”，点击“请 AI 解读当前环境”。
3. 第一次调用还要校准设备时间，以检查加密连接的证书，可能等待更久。
4. 等待文字出现。它只解释点击时的一份数据；之后传感器数字变化，旧回复不会自动更新。

打开页面和查询进度不调用模型。只有手动点击才提交，一台设备每分钟最多接受一次，
多个浏览器共用此限制。请求失败不会自动重试；请求已经到达云端时，即使本地最终超时，
也可能产生费用。实际用量以官方控制台为准。

`?demo=1` 是网页外观演示，不调用 DeepSeek，也不会编造云端回复。

## 发送了什么，保留了什么

发送的内容是本次测量摘要；使用一句话控制时还会发送本次要求。摘要包括温湿度、光照、相对声音指数、MQ-2 相对气体指数、原始 ADC 和
估算电压、有人/移动状态、本地异常分数、学习样本数，以及预热、读数有效性和固件提醒原因。
无效的温度、湿度或光照不会伪装成正常读数。MQ-2 指数不是 ppm，声音指数不是分贝。

照片、录音、Wi-Fi 名称和密码、人员身份不放进请求。请求通过加密连接（HTTPS）直接发往
DeepSeek；对方服务仍能看到网络连接来源 IP，并按其政策处理请求。需要完全本地处理时，
不启用云功能即可。

设备只暂存最后一次云回复，重启后清除，不保存云对话历史。当前没有全天历史数据库，
因此一次解读不能当作日报或长期趋势分析。

## 代码怎么分工

| 文件                                                            | 可以怎样理解                                     |
| --------------------------------------------------------------- | ------------------------------------------------ |
| `include/cloud_config.h`                                      | 私人的门卡，只在本机保存                         |
| `include/services/deepseek_settings.h`                        | 调用地址、冷却时间和内存预算                     |
| `src/services/deepseek_protocol.cpp` / `deepseek_tools.cpp` | 组织请求、工具描述，严格校验文本或操作           |
| `src/services/deepseek_client.cpp`                            | 校时、验证证书、发送官方 HTTPS 请求              |
| `src/services/ai_advisor.cpp`                                 | 复制快照、排队、限制频率、收取后台结果           |
| `src/services/network_ai_routes.cpp`                          | 网页查询进度和提交一次请求的入口                 |
| `web/src/ai-controller.js` / `ai-view.js`                   | 按钮、进度与文字显示                             |
| `src/app/ai_command_handler.cpp`                              | 一次性取走指令，在主循环执行并记录结果           |
| `src/drivers/camera_snapshot.cpp`                             | 实际取帧并缓存最后一张照片，读取缓存不会再次拍照 |

耗时的云请求放在独立后台任务中。可以把任务理解成“另一位专门等电话的工作人员”，
主循环继续采集和处理按键。两个任务用固定大小的队列传递快照和结果，不共同修改告警状态。

`GET /api/ai` 只查询进度，不计费；`POST /api/ai` 使用固件自己的测量数据，可以附带一句
不超过384个UTF-8字节的`prompt`（网页最多120个字符），不接收浏览器自造的测量。
付费入口只接受设备网页同源的 JSON 请求，不是公开聊天代理。
这项检查不等于用户登录；同一局域网里能访问设备的人仍可能触发调用，不要把设备映射到公网。

## 能不能让 AI 控制硬件

已经接上四种实际固件操作。在网页输入框一次只说一件事：

| 你输入的话     | 本机实际做什么                                                 |
| -------------- | -------------------------------------------------------------- |
| 让蜂鸣器响一下 | GPIO21输出固定200ms高电平；需按接线教程接蜂鸣器模块            |
| 静音           | 调用与原网页按钮相同的10分钟静音操作，不停止监测               |
| 恢复声音提醒   | 取消静音，是否响继续由本地风险规则决定                         |
| 拍张照片       | 仅摄像头就绪时提供该工具，实际读取一帧JPEG并缓存，网页随后显示 |

完整调用路线：

```text
你：让蜂鸣器响一下
  → 官方模型提出 beep({})
  → 固件检查：已知工具、恰好一个操作、参数必须为空对象
  → 主循环输出GPIO21短响信号
  → 网页显示固件记录的执行结果
```

只有发送一句话要求时才向模型开放工具；“解读当前环境”按钮不会开放操作工具。
普通刷新、状态轮询和模型文字回复均不会触发硬件。固件拒绝未知工具、额外参数或多个
工具调用；模型不能指定任意GPIO或无限发声时间，也不能清空学习、改阈值。

GPIO只接蜂鸣器模块的信号口，不直接给大功率蜂鸣器供电。真实连接见[接线教程](03-接线教程.md)。
“已输出信号”不能证明蜂鸣器真的发声；拍照成功则表示驱动确实拿到了JPEG。

AI拍到的照片只缓存最后一张在PSRAM中，重启清除；网页从`GET /api/ai/photo.jpg?id=请求编号`
读取原照片，不会重新拍摄，不上传给DeepSeek。图片下载失败不代表固件又拍了一次。

当前未接入舵机、真实灯具或家电控制。若以后增加舵机，仍需独立供电与共地、角度限位、
驱动模块和白名单工具，不能让模型临时决定接线或写寄存器。

## 常见错误

| 现象                  | 先检查什么                                                    |
| --------------------- | ------------------------------------------------------------- |
| 显示尚未配置          | 文件名是不是 `cloud_config.h`，是否启用、填入密钥并重新烧录 |
| 设备需连接家庭 Wi-Fi  | 当前是否只有设备热点；路由器能否访问外网                      |
| 校时失败              | 网络是否允许访问 NTP 时间服务；稍后手动重试                   |
| 无法建立加密连接      | 外网、设备时间和证书链；不要通过关闭证书校验掩盖问题          |
| 密钥无效（401）       | 官方密钥是否复制完整、是否撤销                                |
| 余额不足（402）       | 官方账户的 API 余额                                           |
| 请求过频（429）       | 等待设备或官方的频率限制结束                                  |
| 参数不被接受          | 账户当前支持的模型名及官方接口变更                            |
| 回复超时/中断         | 网络和云端负载；先看用量，再考虑手动重试                      |
| 任务无法启动/内存不足 | 重启并检查可用内存，特别是同时使用相机时                      |

错误不影响本地规则。不要因云服务给出“正常”的文字，就忽略固件提醒、人的感知或正规报警器。

## 过关标准与验证边界

- 未填密钥也能使用本地功能，打开网页不会自动调用模型。
- 填好密钥后点击按钮，得到与本次真实读数对应的中文解读，官方用量能查到调用。
- 等待回复时本地数据、屏幕和实体按键仍工作；断网只让云功能失败。
- 刷新网页不能绕过一分钟冷却，演示模式不消耗额度。

指令并通过固件同一套协议校验（一次验证共678 tokens，费用以官方账单为准）。
这次调用只使用明确标记为测试的设备摘要，没有操作硬件。
固件仍为仅编译验证；元器件未到货，没有烧录或验证GPIO电气信号、实际声音及相机画面。
