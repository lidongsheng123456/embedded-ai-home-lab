# 09 后续升级路线

首版连续稳定运行一周后，再进行下面升级。

## V1.1：声音 TinyML 分类

目标类别建议只做四种：

1. 普通室内背景；
2. 敲门；
3. 商用烟雾报警器的鸣叫；
4. 强烈撞击。

推荐步骤：

1. 每类录制至少 10～20 分钟，覆盖不同距离和背景噪声；
2. 日常谈话录音不上传公共数据集；
3. 使用 Edge Impulse 生成 MFCC 特征和小型分类网络；
4. 将模型量化为 int8；
5. 导出 Arduino/C++ 库；
6. 在 ESP32-S3 上测试延迟、内存和混淆矩阵；
7. 烟雾报警器类别只能作为“听到现有报警器”的辅助转发，不能替代报警器本体。

## V1.2：多时段异常模型

为白天、夜间、在家和无人四种状态分别维护模型，降低开关灯、做饭和睡眠造成的误报。需要加入 NTP 时间同步，并记录模型切换原因。

## V1.3：空调红外控制

增加 940 nm 红外发射管、NPN/MOSFET 驱动和红外接收管。先只实现：

- 网页手动发送已学习的开/关指令；
- 无人一段时间后提示关闭，不直接自动关闭；
- 验证一个月后再允许自动操作。

不同品牌和型号的空调协议差异很大，需要确定具体品牌后使用 IRremoteESP8266 对应协议。红外发射管不能直接由 GPIO 大电流驱动。

## V1.4：历史趋势

ESP32 内存不适合长期保存大量数据。可以选择：

- 只保存最近 24 小时到 LittleFS；
- 使用 microSD 卡；
- 将汇总数据发送到你熟悉的 Java/Rust 后端；
- 使用 MQTT 接入 Home Assistant。

即使增加服务器，本地阈值和蜂鸣报警仍应保留，避免网络中断后完全失效。

## V2.0：正式 PCB

在开发板载板验证稳定后，才考虑 ESP32-S3-WROOM 模组和板载传感器。正式 PCB 需要重新处理：

- USB、ESD 和电源保护；
- ESP32 启动配置；
- 天线净空；
- SCD41 热隔离和气流；
- 麦克风声学开孔；
- 量产烧录与测试点；
- EMC 和长期稳定性。
