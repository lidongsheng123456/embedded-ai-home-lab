# 03 从一根线开始的接线教程

下文逐根杜邦线步骤面向面包板。使用R2载板时，不再按开发板3V3给外围模块供电：
外围走载板独立3.3V，开发板经母座5V排针供电（先按厂家图短接IN/OUT），MQ-2采用10kΩ/10kΩ，上传`carrier_r1_*`环境。
载板插座针序、模块线束和上电步骤以[载板说明](../eda/hardware/README.md)及
[首板验收](../eda/hardware/docs/first-board-validation.md)为准。

## 接线前的五条规则

1. 改线前拔掉两个Type-C接口和外部5V；
2. 模块VCC先查丝印，再决定接3.3V还是5V；
3. 所有模块GND必须与ESP32 GND相连，这叫共地；
4. GPIO只能接受0～3.3V；
5. 每增加一个模块就上电验收，不一次全部接完。

你的N16R8使用OPI PSRAM，GPIO35、36、37不要连接外设。完整摄像头环境在GPIO43输出占位时钟，
因此烧录和串口监视使用开发板上标为USB的原生USB口，不使用标为UART的Type-C口。

## 第一步：只接ST7789屏幕

| ST7789V | ESP32-S3 | 作用 |
|---|---|---|
| GND | GND | 电源负极 |
| VCC | 3V3 | 屏幕电源，不能接5V |
| SCL | GPIO12 | SPI时钟 |
| SDA | GPIO11 | SPI数据，也叫MOSI |
| RES | GPIO15 | 屏幕复位 |
| DC | GPIO14 | 数据/命令选择 |
| CS | GPIO10 | 片选 |
| BLO | 3V3 | 背光常亮 |

这里的SDA不是I2C SDA，只是商家对SPI数据脚的命名。上传core_st7789_154，屏幕出现
HomeGuard Mini才继续。

## 第二步：接SHT40和BH1750

两个模块共享同一组I2C线：

| 模块 | 模块引脚 | ESP32-S3 |
|---|---|---|
| SHT40 | VCC | 3V3 |
| SHT40 | GND | GND |
| SHT40 | SDA | GPIO8 |
| SHT40 | SCL | GPIO9 |
| BH1750 | VCC | 3V3 |
| BH1750 | GND | GND |
| BH1750 | SDA | GPIO8 |
| BH1750 | SCL | GPIO9 |

它们能共用两根线，是因为地址不同：SHT40通常为0x44，BH1750通常为0x23。

## 第三步：搭MQ-2安全分压

### 为什么不能直接接

MQ-2模块使用5V供电，AO最高约4V，超过ESP32允许的3.3V。DO则直接输出0V或5V，本项目
不使用DO。

### 分压电路

    MQ-2 VCC ───────── 5V
    MQ-2 GND ───────── GND

    MQ-2 AO ── 10kΩ ──┬── GPIO3
                       └── 20kΩ ── GND

20kΩ可以由两只10kΩ串联得到。中间连接点才接GPIO3，不要把AO直接接GPIO3。

上述面包板接法适用于已确认 AO 最高约 4 V 的模块。若 AO 可能接近 5 V，应把下方电阻改为 10 kΩ，并使用下面的载板编译环境以匹配分压系数。

R2 载板已在板上设计 10 kΩ / 10 kΩ 分压和 100 nF 滤波，使用 `carrier_r1_core_st7789` 或 `carrier_r1_full_st7789_camera`。MQ-2 原始 AO 直接接载板 J1 的 3 脚，不再外加面包板分压。J1 的 1、2 脚分别为 +5V、GND；转换线按模块丝印接，不能假定针序相同。整板设计状态见[载板说明](../eda/hardware/README.md)。

第一次上电先不要接GPIO3：

1. 给MQ-2的VCC和GND供电；
2. 万用表黑表笔接GND，红表笔测分压中点；
3. 确认中点始终低于3.3V；
4. 断电后再把中点连接GPIO3。

金属网在工作时温热属于正常现象。不要用打火机放气或明火测试。

## 第四步：接LD2410C

你购买的模块针脚从图片可读为TX、RX、OUT、GND、VCC：

| LD2410C | ESP32-S3 |
|---|---|
| VCC | 5V |
| GND | GND |
| TX | GPIO17，ESP接收 |
| RX | GPIO18，ESP发送 |
| OUT | 不接 |

TX必须接对方RX，RX必须接对方TX。雷达默认波特率为256000。

## 第五步：接INMP441

| INMP441 | ESP32-S3 |
|---|---|
| VDD | 3V3 |
| GND | GND |
| SCK/BCLK | GPIO4 |
| WS/LRCL | GPIO5 |
| SD | GPIO6 |
| L/R | GND |

INMP441不能接5V。L/R接GND表示使用左声道，悬空可能导致始终读不到声音。

## 第六步：蜂鸣器和按钮

| 器件 | 连接 |
|---|---|
| 蜂鸣器VCC | 3V3 |
| 蜂鸣器GND | GND |
| 蜂鸣器I/O | GPIO21 |
| 静音/多功能按钮一端 | GPIO39 |
| 按钮另一端 | GND |

在无摄像头的core_st7789_154环境中，还可以增加：

| 器件 | 连接 |
|---|---|
| 重新学习按钮一端 | GPIO38 |
| 重新学习按钮另一端 | GND |

full_st7789_camera环境把GPIO38用于图像数据，因此只保留GPIO39。R2载板的两个编译环境也统一使用GPIO39单按钮：

- 短按后松开：静音10分钟；
- 按住至少2秒再松开：重新学习。

## 第七步：OV2640独立验机接线

购买的模块带板载有源晶振，没有MCLK针。按照板上丝印连接：

| OV2640 | ESP32-S3 |
|---|---|
| 3.3 | 3V3 |
| GND | GND |
| SCL | GPIO9 |
| SDA | GPIO8 |
| D0 | GPIO1 |
| D1 | GPIO2 |
| D2 | GPIO7 |
| D3 | GPIO13 |
| D4 | GPIO38 |
| D5 | GPIO40 |
| D6 | GPIO41 |
| D7 | GPIO42 |
| PCLK | GPIO16 |
| VSYNC | GPIO47 |
| HREF | GPIO48 |
| RST | 3V3 |
| PWDN | GND |
| FLASH | 暂时不接 |

GPIO43保持悬空。固件会在GPIO43生成一个未连接的占位XCLK，只为满足ESP32 Camera驱动
的初始化要求；摄像头模块实际使用板载有源晶振。

GPIO44连接开发板CH343的发送输出，因此摄像头PCLK改用GPIO16。不要把旧版接线图中的
GPIO44继续接到PCLK；只拔掉UART口的USB线不能证明CH343输出已断开。

摄像头D0～D7、PCLK、VSYNC和HREF属于高速信号，母对母杜邦线尽量短于10cm。第一次只接
摄像头并上传camera_ov2640_check，不连接屏幕和其他传感器。

## 完整系统引脚总表

| 功能 | GPIO |
|---|---|
| I2C SDA/SCL | 8 / 9 |
| ST7789 MOSI/SCLK/CS/DC/RST | 11 / 12 / 10 / 14 / 15 |
| INMP441 BCLK/WS/SD | 4 / 5 / 6 |
| LD2410C RX/TX | 17 / 18 |
| MQ-2分压AO | 3 |
| 蜂鸣器 | 21 |
| 多功能按钮 | 39 |
| 摄像头D0～D7 | 1 / 2 / 7 / 13 / 38 / 40 / 41 / 42 |
| 摄像头PCLK/VSYNC/HREF | 16 / 47 / 48 |
| 摄像头驱动占位XCLK | 43，保持悬空 |

## 上电前最终检查

- 3V3与GND没有直接短路；
- MQ-2 AO经过与固件匹配的分压：面包板10kΩ/20kΩ（AO最高约4V），或R2载板10kΩ/10kΩ；
- INMP441、ST7789和OV2640接3.3V；
- MQ-2和LD2410C接5V；
- GPIO35、36、37没有接线；
- 摄像头RST接3.3V，PWDN接GND；
- 所有GND互相连接；
- 使用原生USB口烧录完整摄像头环境。
