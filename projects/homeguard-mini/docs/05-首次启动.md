# 05 怎么判断每个模块真的正常

**一次只加一件。编译成功不等于模块正常，必须观察下面的实际现象。** 改线先断电，不带电插拔。

本章为待执行的验收方法，当前固件**仅编译验证**。载板先做[空载电源检查](../eda/hardware/docs/first-board-validation.md)，再使用 `carrier_r1_*` 环境；开发板插在载板上运行时用屏幕/网页看状态，不接开发板USB。

## 面包板逐项打勾

| 顺序 | 你做什么 | 通过标准 |
| --- | --- | --- |
| 1 开发板 | 不接外设，烧 `camera_ov2640_check`，看Monitor | `PSRAM: found=1, size=8388608 bytes`；未接相机时相机失败正常 |
| 2 ST7789 | 烧 `core_st7789_154`，只接屏幕 | 有HomeGuard Mini、数据栏目，联网后有IP |
| 3 SHT40 | 加温湿度模块，观察正常环境和轻微哈气后的读数 | `SHT4x=1`，温湿度有合理变化；不让水汽凝结 |
| 4 BH1750 | 加光照模块，手遮挡，再用手电照 | `BH1750=1`，lux明显一降一升 |
| 5 MQ-2 | 先测AO及分压点，再断电接GPIO3 | 分压点始终低于3.3V，原始值/估算电压有变化 |
| 6 LD2410C | 正前方1～3米走动、静坐、离开 | 有人/移动随之改变；断开后显示未知 |
| 7 INMP441 | 安静，再距离1～2米拍手 | 声音指数明显升高，不是始终0或满值 |
| 8 蜂鸣器 | 测短响，再操作静音 | 执行命令后停止，静音显示10分钟；慢网页可能推迟执行 |
| 9 按钮 | 按下、松开，观察静音和样本数 | 按下不重复执行，松开产生一次操作，见下表 |
| 10 OV2640 | 仅接相机，烧 `camera_ov2640_check` | `PASS`，持续出现 `JPEG 640x480, … bytes` |
| 11 完整系统 | 面包板烧 `full_st7789_camera`，网页点击拍照 | 能显示一张新JPEG，其他数据继续更新 |

所有接线按[03](03-接线教程.md)，烧录操作按[04](04-软件与烧录.md)。不通过先看[08 排错表](08-故障排查.md)，不要一次改几样东西。

### 按钮按哪个、按多久

| 版本 | 操作 |
| --- | --- |
| 面包板核心，双键 | GPIO39静音；GPIO38重新学习；松开触发 |
| 面包板带相机 / R2载板，单键 | GPIO39短按后松开静音；按住至少2秒再松开重新学习 |

重新学习会清掉旧样本。慢网页时按键先被记录，业务操作可能稍后才执行；不是严格实时保证。

## MQ-2需要额外等一等

1. **新模块第一次**：通风、安全、远离易燃物，连续通电至少24小时，让读数稳定；这段不作为正常基准。
2. **以后每次开机**：等待3分钟预热。期间停用气体规则和本地模型，其他有效指标仍可提醒。
3. 检查 `gasRaw`、`gasVoltage`，不能只看有没有数字；悬空引脚也可能产生数字。

酒精、清洁剂、做饭气味、湿度都可能影响读数。**不用明火、打火机放气或大量烟雾测试。**

## 网页也要验收

- 用屏幕显示的实际IP访问，不加 `?demo=1`。
- 手机、电脑各试一次：能拖动房间，数据会更新，遮挡光照传感器时明暗示意变化。
- 雷达无人时人物消失；人物位置只是示意，不是真实定位。
- 只有点击拍照才产生快照，不是连续视频，也不保存历史照片。
- 断开设备网络后应显示离线，并禁用静音、学习、拍照。

## 断线后能不能恢复

| 测什么 | 操作与预期 |
| --- | --- |
| 路由器断网 | 约15秒出现设备热点；每30秒尝试重连，恢复后热点关闭，按新IP访问 |
| 传感器断开 | **断电拔一个，再上电**；温湿度/光照应显示`null`或`--`，不是正常的0 |
| 雷达断开 | 超过500ms无有效报告显示未知，不是假装无人 |
| 麦克风异常 | 读失败应未知；全零也可能是线路固定为0，仍需拍手验证 |

雷达启动的 `receiver=1` 只证明接收任务已启动，不证明数据线接对。初次联网期间IP暂为 `0.0.0.0` 可以等待，但持续如此需排错。

## 最后再连续跑48小时

记录有无重启、I2C失联、拍照失败、Wi-Fi切换异常、MQ-2正常范围，以及屏幕/主控发热是否影响温度读数。通过后才固定接线、焊板和做外壳。

载板还须实测启动压降、峰值电流、温升和信号波形，不能用“网页能打开”替代[首板验收](../eda/hardware/docs/first-board-validation.md)。
