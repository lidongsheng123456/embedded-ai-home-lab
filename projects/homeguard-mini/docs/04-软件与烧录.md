# 04 在哪里编译、烧录、看日志

**用VS Code打开整个 `projects/homeguard-mini/firmware` 文件夹，再选指定环境。不要只打开一个cpp文件。** 左侧文件树顶层应能看到 `platformio.ini`。

## 第一次准备

1. 安装VS Code和扩展 **PlatformIO IDE**，等待初始化完成。
2. 安装Node.js 20或更高版本（含npm），用于把网页打包进固件。
3. 在终端检查 `node --version` 和 `npm --version`，能显示版本再继续。
4. 用数据线连接开发板标着 **USB** 的原生USB接口。

全程使用原生USB，能避免“烧录用一个口，日志却出在另一个口”的困惑。固件启用了USB串口功能（CDC），Monitor设置115200。COM号以设备管理器拔插时出现的端口为准，不固定为COM5或COM6。

**载板上的开发板先断电取下，再接电脑USB。烧录后拔USB，才能装回上电。** 开发板插在载板上运行时，通过Wi-Fi看数据，不同时插开发板USB。

## 第一步：配置Wi-Fi

在 `firmware` 的终端运行一次：

```powershell
Copy-Item include\app_config.example.h include\app_config.h
```

编辑新文件，填2.4GHz Wi-Fi名称和密码。已有配置就直接编辑，**不要重复复制覆盖**。这个私人文件已被Git忽略。

不填家庭Wi-Fi也能使用本地功能：设备会开 `HomeGuard-Mini` 热点。模板默认密码是 `homeguard123`，首次使用请改成自己的强密码。

## 第二步：选对环境

“环境”就是一套板型、屏幕和功能配置。一次只选一行：

| 你正在做什么 | 环境名 |
| --- | --- |
| 面包板：ST7789屏 + 核心传感器 | `core_st7789_154` |
| 只验OV2640，不接其他模块 | `camera_ov2640_check` |
| 面包板：核心 + 已验证的相机 | `full_st7789_camera` |
| 使用旧ILI9341屏 | `core_ili9341_240x320` |
| R2载板：核心 | `carrier_r1_core_st7789` |
| R2载板：核心 + 相机 | `carrier_r1_full_st7789_camera` |

载板环境名中的r1为兼容保留，**不是旧USB短线供电方案**。载板分压还原系数2，原面包板为1.5，要和[实际电阻](03-接线教程.md#第三步搭mq-2安全分压)匹配；改了分压后重新学习。

相机诊断环境只有串口报告，没有正常网页、屏幕、传感器或DeepSeek。完整相机程序占用GPIO43，必须使用原生USB；GPIO44不能接相机PCLK。

## 第三步：依次点击这三个菜单

左侧 **PlatformIO图标 → PROJECT TASKS → 指定环境 → General**：

| 顺序 | 点击 | 作用 | 通过标志 |
| --- | --- | --- | --- |
| 1 | Build | 把代码编译成固件，不改开发板 | 末尾`SUCCESS` |
| 2 | Upload | 编译后写入开发板 | 写入完成，无FAILED |
| 3 | Monitor | 打开串口，看运行文字 | 复位后能看到启动日志 |

`Clean`只清旧编译缓存，正常不必每次点。首次Build会下载库并打包Three.js网页，出现npm输出正常。**网页随固件一起烧入，不需要Upload Filesystem。**

如果Upload卡在 `Connecting`：按住BOOT → 短按RESET → 开始写入后松BOOT → 烧录完短按RESET。

Monitor前关闭VOFA、串口助手和其他Monitor，避免争抢同一COM口。退出Monitor按 `Ctrl+C`。

## 第四步：看日志、打开网页

核心传感器接好后应出现类似文字（数值只是示例）：

```text
Sensors: SHT4x=1 BH1750=1 MQ2=GPIO3 (3 min warm-up)
Sensor: LD2410 receiver=1 (awaiting valid data frames)
```

`receiver=1`只表示雷达接收任务已启动；收到有效报告、有人/无人状态随实际变化，才算雷达通信通过。

相机诊断应看到 `PSRAM: found=1, size=8388608 bytes` 和JPEG尺寸/字节数。字节数随画面变化正常。

- 家庭Wi-Fi连上：访问屏幕/串口显示的实际IP。
- 热点模式：手机连接HomeGuard-Mini，浏览器打开 `http://192.168.4.1`。提示没互联网时选择保持连接。
- 网页地址加 `?demo=1` 是模拟展示，**不能用来验收传感器**。

每次改代码：Build → Upload → Monitor → 核对真实现象。当前固件**仅编译验证**，具体验收看[05](05-首次启动.md)，出错看[08](08-故障排查.md)。
