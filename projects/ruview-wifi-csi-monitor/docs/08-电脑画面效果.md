# 08 电脑端能看到什么画面

## 有电脑屏幕界面

RuView 的正式显示端是电脑浏览器。ESP32-S3 只负责采集并发送 CSI，本身不接显示屏。

启动 sensing server 后，在电脑打开：

```text
主界面：http://127.0.0.1:3000
Dashboard：http://127.0.0.1:3000/ui/index.html
Observatory：http://127.0.0.1:3000/ui/observatory.html
```

不同上游版本的页面布局可能变化，但数据来源和能力边界相同。

## 单块 ESP32-S3 的真实画面

使用本教程的一块 ESP32-S3 时，应该重点观察：

- 节点是否在线、节点 ID；
- UDP/CSI 实时帧率；
- Wi-Fi RSSI；
- CSI 子载波幅度、相位或相关波形；
- Presence：当前 RF 链路是否检测到人体影响；
- Motion：运动能量或运动等级；
- 置信度、信号质量和丢包情况；
- 人进入、静坐、走动、离开时曲线如何变化。

电脑画面更接近“无线电监测仪表盘”，例如：

```text
Node 1        Online
CSI rate      10～20 fps（以实际环境为准）
RSSI          -48 dBm
Presence      Present
Motion        0.13
Confidence    0.80

CSI幅度/相位：～～～～实时曲线～～～～
```

数字只是示意，不能当作你的实测标准。

## 网上那种发光人体骨架画面

上游项目确实提供 Three.js Observatory，视觉上可能包含：

- 黑色三维空间；
- Wi-Fi 波纹或点云；
- 发光人体轮廓；
- 17个关节点；
- Presence、Motion、RSSI；
- 呼吸、心率、人数等卡片。

但是上游示例图右上角明确标有 `DEMO`。使用一块 ESP32-S3 并不等于能可靠得到该骨架。

| 画面内容 | 单节点真实性/成熟度 |
|---|---|
| 节点在线、RSSI、CSI帧率 | 真实且可验证 |
| CSI幅度/相位曲线 | 真实且可验证 |
| 人体存在、运动变化 | 可以实验，属于启发式/模型判断 |
| 精确人数 | 单节点不可靠 |
| 呼吸和心率 | 实验性质，不能作为健康数据 |
| 17关键点人体骨架 | 不能期待开箱即用，当前实时模型仍弱 |
| 精确穿墙位置 | 需要多节点和房间校准，单节点不可靠 |

如果没有 ESP32 硬件，Docker 模拟模式也会显示漂亮的人体动画，但那是合成数据，不是房间中的你。

## 如何确认屏幕显示的是真实数据

执行以下实验：

1. 服务端必须使用 `--source esp32`，不能使用 `auto` 或 `simulated`；
2. 页面显示真实节点 ID、RSSI和帧率；
3. 拔掉 ESP32 电源，节点和 CSI 数据应停止；
4. 恢复供电，节点重新上线；
5. 人在路由器与 ESP32 之间走动，Motion和CSI曲线重复变化；
6. 如果拔掉 ESP32 后骨架仍然持续自然运动，该骨架不是你的真实 CSI 结果。

## 想得到更接近三维监控的效果

至少需要：

- 3块 ESP32-S3，从不同方向形成 RF 链路；
- 固定路由器信道和节点位置；
- 采集空房、有人、不同位置和动作数据；
- 对当前房间进行校准或监督训练；
- 使用摄像头提供训练标签时，摄像头只用于数据采集阶段；
- 用独立测试数据验证，不能只看动画是否“像”。

即使完成这些，它仍然是实验性 RF 感知系统，不是摄像头那样清晰、稳定的视频画面。
