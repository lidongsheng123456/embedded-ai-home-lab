# 从接线到 PCB：用 HomeGuard 讲清楚硬件设计

你可以把做板子理解成：**先让一组零件通过接线配合工作，再把这些接线整理成一块结实、可靠、容易装进盒子的电路板。**

但 PCB 不是把面包板上的线照抄一遍。还要确认电源够不够、针脚有没有认反、插头能不能插进去，以及电流会不会干扰旁边的信号。

这篇讲可以用于其他项目的方法，HomeGuard 的具体针序以[接线教程](../projects/homeguard-mini/docs/03-接线教程.md)和[当前载板接口](../projects/homeguard-mini/eda/hardware/README.md)为准。当前固件**仅编译验证**，载板已有软件设计检查，整机尚未完成实物验证。

## 1. 知道你准备用哪些器件吗？

知道，目前是下面这套。这里的“使用”指当前设计目标，不表示这些模块都已经通电实测通过。

| 器件 | 通俗理解与用途 | 供电与传话方式 |
| --- | --- | --- |
| 泽杰 ESP32-S3 N16R8 双 Type-C 开发板 | 大脑：读数据、判断状态、联网、更新界面 | 载板给开发板 5V；GPIO 信号按 3.3V 使用 |
| ST7789V 1.54 寸 240×240 彩屏，8 针 | 本机的小仪表盘 | 3.3V；SPI，几根线传命令和画面 |
| SHT40 | 测温度、湿度 | 3.3V；I2C |
| BH1750 / GY-302 | 看环境亮不亮 | 3.3V；I2C |
| MQ-2 模块 | 对烟雾和部分气体有反应，作为相对变化参考 | 5V 加热；AO 输出电压，必须分压后再读 |
| LD2410C 五针雷达 | 检测正面区域是否有人、是否移动 | 5V 供电；UART 串口传数据 |
| INMP441 麦克风 | 听环境声音的强弱变化 | 3.3V；I2S 数字音频 |
| OV2640 带板载晶振的 DVP 模块 | 拍照 | 3.3V；多根数据线并行传图像，另有控制线 |
| 有源蜂鸣器模块 | 发出提醒声音 | 选支持 3.3V 供电、高电平触发且自带驱动的模块 |
| 轻触按键 | 短按静音、长按重新学习 | GPIO 输入上拉，另一端接 GND |

N16R8 表示有 **16MB 程序存储空间和 8MB 运行时扩展内存**，不能由此推断任意引脚都能随便使用。舵机、WS2812 灯板和喇叭不属于这版核心载板的既定负载，加入时需要重新分配引脚、接口和电流。

这些传感器多数是**外接模块**，通过插座和线束接到载板上。不是把所有传感器裸芯片都直接焊在这块板子上。

### 它们为什么能共用一些线？

I2C 可以理解为一条有编号的公共通道。ESP32 先叫设备的地址，再与它交换数据。SHT40 常用地址 `0x44`，BH1750 常用 `0x23`，所以能共用 GPIO8、GPIO9 两根线。实际还要核对地址、通信规则和上拉电阻，不能把任意两种设备直接并起来。

SPI 屏幕有自己的时钟、数据线和片选线；UART 雷达是发送、接收两根线；I2S 麦克风按音频节拍传数据。**插头针数相同，不代表说的是同一种话，也不代表针序相同。**

## 2. 原理图到底根据什么画？

原理图是“谁应该和谁连接”的关系图。设计至少要把四类证据对上：

| 依据 | 用来确认什么 | 不能替代什么 |
| --- | --- | --- |
| 你的具体模块照片、丝印和厂家答复 | 买的是哪个版本、接口在哪、供电怎么接 | 模糊照片不能证明针距、针序或最大电流 |
| 厂家尺寸图与芯片数据手册 | 每脚功能、电压范围、电流要求、焊盘尺寸、推荐外围电路 | 同名其他厂家的资料不能随意套用 |
| 固件引脚配置和编译配置 | 软件实际用了哪根脚、什么屏幕、什么分压比例 | 编译通过不能证明线没接反 |
| 当前原生原理图与 PCB 回读检查 | 图中实际连接、板上实际铜线、规则检查结果 | 不能代替上电测量和实物插合 |

**AI 给出的接法是需要核对的设计建议，不是器件规格书。** 找不到型号或厂家资料时，要明确留下待确认项，不能拿“类似模块应该一样”当成结论。

在这个项目里，可以沿着这些文件核对：

- [器件规格](../projects/homeguard-mini/docs/02-材料清单.md)：当前使用什么模块。
- [pins.h](../projects/homeguard-mini/firmware/include/pins.h)：软件把哪些 GPIO 分给谁。
- [platformio.ini](../projects/homeguard-mini/firmware/platformio.ini)：板型、屏幕驱动和不同构建环境。
- [电气设计依据](../projects/homeguard-mini/eda/hardware/docs/electrical-review.md)：电源、保护器件的原厂资料和计算依据。
- [原生工程入口](../projects/homeguard-mini/eda/README.md)：实际要加工的 PCB2。

历史设计 JSON 只是当时的输入，部分仍含旧供电方案。不能把它们重新运行一遍就认为得到了当前 PCB。

## 3. 先想供电，再想信号

把电源想成送水：**电压类似水压，电流类似流量；电源标 3A，表示它能提供的能力，不是强行往设备里灌 3A。** 这个比喻只帮助入门，实际选择仍看器件规格和测量。

HomeGuard 当前的大致供电关系是：

```text
专用 5V/3A 电源和线
        │
板边 USB-C J10
        │
保险丝 + 电子限流保护
        ├── 5V 模块：MQ-2、雷达
        ├── 反向阻断与缓慢上电 → J7.21 → ESP32 开发板 5V
        └── 降压器 → 外围 3.3V → 屏幕、相机、环境传感器等

所有模块的 GND 相连，作为共同的电压参考和电流返回路径。
```

这里有几个特别容易误解的地方：

1. **GPIO 是发指令、读信号的口，不是大功率电源口。** 舵机、电机、灯带等从合适的电源取电，GPIO 通过合适的信号接口或驱动电路控制它们，并按要求共地。
2. **模块吃 5V，不等于它的信号也能直接接 ESP32。** MQ-2 的 AO 可能过高，载板用两只 10kΩ 电阻，把电压降为一半：5V 变 2.5V。软件按系数 2 还原；面包板旧接法的系数 1.5 不能混用。
3. **共地，不等于两路 3.3V 输出直接接在一起。** 开发板自己有稳压器，载板也有稳压器。它们的输出存在误差，直接并联可能互相送电，当前设计将它们分开。
4. **保护电路各管不同的事。** 保险丝负责后备熔断；电子限流在电流过大时限制输出；缓慢上电减轻电容刚通电时的冲击；反向阻断减少电流倒着流。任何一个都不能保证整机对所有误接都安全。
5. **3A 电源不等于板子所有接口都能用 3A。** 当前整机设计分配为约 1.60A 输入，电子保护典型限流约 2.04A。它们是设计值，仍须实测启动峰值、压降和温升。

### 为什么开发板还要求短接 IN/OUT？

这是你这款开发板的厂家要求，不是所有 ESP32 板都如此。厂家标出的 **IN/OUT 两块焊盘**需要短接，才能按当前方案从排母给它供电。不是短接 5V 和 GND，也不要凭名称猜焊盘位置。

厂家说明开发板没有防倒灌保护，你已选择：**断开载板电源 → 取下开发板 → 接电脑 USB 烧录 → 拔 USB → 装回载板 → 上电**。载板上的保护不能被理解成开发板两个 USB 口已经可以同时随便接。

## 4. 从原理图变成 PCB，多了哪些事？

PCB 就是电路板。原理图说“这两脚要连起来”，PCB 还得决定：零件放哪里、脚底下用多大的焊盘、铜线从哪里绕、板子开多大孔。

其中“封装”指零件在板上的落脚位置：焊盘大小、脚间距、外形和方向。**原理图符号正确、封装脚号却反了，做出来仍会接错。**

### 第一步：先定能不能装进去

先确定板框、安装孔、开发板母座、USB 和对外插座，再安排小电阻电容。否则最后才发现插头被挡住，只能重摆重布。

HomeGuard 的 USB-C J10 已调整到板边附近。检查时还要看外壳壁厚和插头塑料头，不能只看金属插座有没有靠边。开发板母座按厂家给出的双排 22 针、2.54mm 针距、25.40mm 排距设计，仍需拿实物套合。

XH 常见 2.50mm 间距，普通排针常见 2.54mm；外观看着接近，不能当成同一种连接器。插座本身摆得下，也不代表插上带锁扣的插头后还放得下。

### 第二步：按功能分区域

- 电源输入、保护、稳压器放成清楚的一条路径，大电流尽量就近走。
- 插座按实际线束出线方向安排，留出插拔手指和线弯曲的空间。
- 开关稳压器会快速切换电流，相关电感、电容和铜线要紧凑，避免靠近敏感的模拟采集线路。
- 温湿度模块在盒内要远离 MQ-2 加热器和稳压器，留通风空间；载板布局与盒内模块摆放都要考虑。
- 外接天线及其馈线要留空间，不能认为用了外接天线就不用考虑遮挡和走线。

这相当于软件按职责分模块：电源区负责供电，接口区负责接模块，主控区负责处理数据。先把边界定清楚，后面才容易检查和修改。

### 第三步：先处理关键铜线

布线不是把所有细线随便绕通。一般先照顾电源、稳压器附近的电流回路、摄像头时钟等关键线路，再处理普通控制线。

**电流必须走回来。** 信号从主控到模块时，也需要通过地返回。地层像连续的返回道路；若被切断或绕很远，可能干扰更大。因此这块板使用四层，两内层为地，外层安排信号和电源。它是这版设计的选择，不代表所有简单学习板都必须四层。

线宽要结合电流、铜厚、长度、压降和允许温升。当前主 5V 路径采用 40mil，外围 3.3V 主干采用 24mil；`mil` 是长度单位，1mil = 0.0254mm。这些数值不能照搬成“所有 5V 线都必须这么宽”。

“过孔”是让铜线从一层走到另一层的小孔。电源经过它时要核算载流能力和连接方式，不是孔越多越好。细焊盘出口可能需要短距离收窄，要看实际长度与负载，不能只看主干很粗就认为整条路都没问题。

### 不用迷信几个口诀

45° 转角、线间距取几倍线宽、所有信号等长，都不是可以替代分析的万能规则。摄像头、屏幕还要看信号变化有多快、有没有完整返回路径、线束多长，以及实测波形。低速按键线通常不需要像相机数据线一样处理。

芯片旁的小电容也不是随便摆的装饰。它相当于附近的小水箱，给瞬时用电补充电荷；摆得太远、连接绕太长，效果会变差。具体位置按芯片厂家的推荐布局核对。

## 5. 本项目遇到过哪些具体的坑？

| 容易做错的事 | 为什么有问题 | 当前处理 |
| --- | --- | --- |
| 把 GPIO44 分给摄像头像素时钟 | 这块开发板的 CH343 发送端也接在这里，两边可能同时驱动 | 相机 PCLK 改到 GPIO16 |
| 把 GPIO35/36/37 当普通空闲脚 | N16R8 版本的 OPI 扩展内存占用相关引脚 | 留给内存使用，不分配给外设 |
| 认为相机插头针数差不多就能直插 | 用户模块是双排 18 针，载板 J12 是自定义 20 针，方向和定义也要核对 | 按[逐根线表](../projects/homeguard-mini/eda/hardware/docs/camera-adapter.md)做短转换线 |
| 模块没上电，但信号线已接高电平 | 电可能沿信号脚倒着进入未供电模块 | 加信号开关，两路 3.3V 稳定后才接通 |
| 认为信号开关能把 5V 变 3.3V | 它只负责接通、断开，不负责变换电压 | MQ-2 另加分压；不能称为电平转换或电气隔离 |
| 分压电阻改了，固件没改 | 采到的电压还原比例就错了 | 载板使用对应 `carrier_r1_*` 环境，历史环境名保留兼容 |
| USB 放在板子中间 | 线头和外壳不方便配合 | 输入 USB-C 移到板边，并保留装配复核 |

这些问题靠“程序没报错”发现不了，必须把开发板原理图、固件分配、载板连接和实际模块放在一起看。

## 6. 软件检查通过，为什么还要拿实物测？

EDA 的自动规则检查叫 DRC，类似代码里的静态检查。它能发现很多短路、间距不足和未布通，但只能按你设置的规则工作。

它通常不能替你确认：买到的模块是不是另一个版本、相机转接线有没有接反、塑料插头是否挡住外壳、MQ-2 的热量是否影响温度，以及 Wi-Fi 和相机一起工作时电源会不会掉压。

本次原生 PCB DRC 检查为 0 项，另有辅助制造检查提示。辅助工具可能用长方形包络估算特殊焊盘，从而误报；遇到这种情况要核对真实铜形状、原厂封装和板厂能力。**不能为了清零而关闭必要规则，也不能把所有提示都当作无关紧要。** 当前处置记录在[制造检查说明](../projects/homeguard-mini/eda/hardware/docs/fabrication-review.md)。

代码编译通过也只说明程序能生成，不证明相机拍得清楚、传感器读得准或设备长期运行稳定。

## 7. 从面包板到第一块成品，按什么顺序？

1. **逐个模块在面包板上跑通。** 先看串口日志和读数，再把模块组合起来；一次加太多，出了问题不好定位。
2. **固定接口。** 记录实际型号、供电、GPIO、插头针序；一起更新固件和接线文档。
3. **画原理图并核对电源。** 确认电流预算、输入电压、保护、分压和未使用脚的处理。
4. **核对封装和机械尺寸。** 先确认母座、USB、安装孔和插头能配合实物，再布板。
5. **布局布线，交叉检查。** 原理图连接正确，还要看铜线、返回路径、发热与装配；保存并重新打开后检查。
6. **把完整工程提交 Git。** 需要时可追踪哪次改了什么；不靠堆一排“最终版”“最终最终版”。有新改动时先保留，再选择性恢复需要的文件。
7. **首板先不上模块检查。** 看焊接、测有无短路；再用可限流电源验证裸载板电压，逐个增加模块。
8. **全负载和长时间运行。** 同时开 Wi-Fi、屏幕、摄像头，测电压、电流、温度，检查复位和通信错误，再根据结果修订。
9. **最后定外壳。** 验证散热、通风、开孔、天线和维护方式，再决定是否需要改第二版板子。

HomeGuard 直接打开[完整原生工程中的 PCB2](../projects/homeguard-mini/eda/README.md)打样，目录保留历史名称。工程内文件要一起保留；加工资料从当前板按需生成。详细上电操作见[首板验收](../projects/homeguard-mini/eda/hardware/docs/first-board-validation.md)，当前未解决事项见[验收清单](../projects/homeguard-mini/docs/10-遗留问题与验收清单.md)。

## 8. AI 帮你设计时，你最值得学会检查什么？

不必先背完芯片手册。先能回答下面几个问题，就能避免很多返工：

- **有没有接错电？** 模块吃几伏、信号最多几伏，GND 接好了没有？
- **这根脚真的空闲吗？** 是否被开发板上的内存、USB、串口芯片占用？
- **图、代码和实物说的是同一件东西吗？** 端子方向、GPIO、分压系数和屏幕型号是否一致？
- **结论靠什么证明？** 是照片推测、手册规定、软件检查，还是万用表和示波器测出来的？
- **出了问题怎么定位？** 能否断电后一次只保留一个模块，观察电压和日志，缩小范围？

你负责的不只是付钱买器件，而是逐步学会判断一条建议有没有依据、一步实验是否真的通过。HomeGuard 是学习和辅助提醒设备，即使完成这些步骤，也不能把它当成经过生命安全认证的报警器。
